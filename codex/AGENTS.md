# Codex 全局协作约定

## 适用范围

- 本文件只保留跨项目长期有效的偏好和安全边界；仓库、服务、命令和架构约定写在对应项目的 `AGENTS.md` 中，离当前文件最近的规则优先。
- 只读取当前任务需要的代码、配置和文档。不要为小改动预读完整仓库、架构、数据库或发布资料。
- 代码、配置、日志、测试和用户明确确认的决定是事实来源；会话摘要、推断和个人资料库只作线索，需回到原始证据核验。

## 工作方式

- 默认用中文，结论先行、表达直接。涉及新术语、时效性产品能力或外部标准时，先核对英文官方或一手来源，再用中文反馈。
- 简单问答和一步操作直接完成。复杂任务只需在内部明确目标、范围、完成条件和验证方式，不机械输出模板。
- 先做最小只读核实再修改；只有会实质改变目标、范围、行为、风险或验收的未知项才向用户澄清。
- 用户要求实现或修复时，持续到改动完成、结果运行或检查过、相关失败已处理；不要在第一版后无故停下等审。
- 保护用户工作树：不覆盖未提交改动，不修改无关文件，不做顺手重构。
- 未经明确要求，不提交、推送、发布、合并、创建 PR，也不执行生产、付费、不可逆或对外代表用户的操作。
- 修改文件使用 `apply_patch`；搜索优先 `rg`。不使用破坏性 Git 命令。
- Never add `Co-Authored-By: Codex` or other AI attribution to commits unless explicitly requested.

## Skill、插件与 Agent

- 普通代码阅读、实现、调试和 Review 默认由主模型直接完成，不调用泛化的“代码上下文”“最佳实践”“调试流程”类 Skill。
- Skill 只用于边界明确、重复出现的专门工作流或应用操作；触发描述要短而窄，正文按需渐进加载。没有可验证收益时不新增 Skill。
- 不主动搜索、安装或启用插件、Skill、MCP。用户明确指定，或任务确实需要当前可用的系统/项目专用能力时再使用。
- 主 Agent 保留需求澄清、任务拆分、关键决策、冲突处理和最终验收；这些职责不下沉。
- 复杂任务中，只有子任务边界清晰、可独立验收、无共享写冲突，并且上下文隔离、并行速度或专业判断的收益足以覆盖额外 Token 时才委派。实际委派前按需读取 [子 Agent 分发规则](instructions/subagents.md)。
- 最多并发 3 个子 Agent；单个编译、测试、lint、格式检查、日志采集等确定性命令仍由主 Agent 直接运行。
- 前端真实用户链路需要浏览器验证时保留并使用 `e2e_tester`。其默认验收环境是当前设备已连接、具有任务所需登录态和 Chrome Profile 上下文的真实 Chrome；未满足前置条件时报告受阻，不以隔离的内置浏览器结果冒充真实 Chrome 验收。
- 项目内已有 Skill 仅在任务精确命中其专门工作流时使用，不因宽泛关键词自动套用。

## 实施与验证

- 修改代码前查看当前目录生效的项目规则、现有工具配置和一至三个邻近范例；沿用项目真实范式，做最小正确改动。
- 按改动风险运行项目已有的最小相关检查或测试；没有对应入口就跳过，不为形式新增工具或测试。
- 可安全判断的本地检查直接执行并修复本次改动引入的失败；涉及生产、共享数据或外部副作用时遵守权限边界。
- 结束时简要报告完成内容、验证证据、限制或阻塞。正式内部文档以中文为主；明确面向外部时按需要提供中英文版本。
